> [!note] 摘要
> 系统梳理 decoder-only Transformer 的三层量化分析框架：**参数量**（各模块来源与总公式）、**计算量 FLOPs**（前向/训练/推理的 prefill 与 decode 分离推导）、**显存占用**（训练时参数+梯度+优化器+激活，推理时权重+KV cache）。覆盖标准 MHA 及 SwiGLU、GQA/MQA 等现代变体，附经典近似公式与 scaling 规律。运行性能、系统瓶颈、分布式代价已拆分至 大模型系统性能优化。

# 大模型参数计算

## 全局结构

| 层级  | 主题             | 核心问题                                                  |  状态   |
| :-: | -------------- | ----------------------------------------------------- | :---: |

| 第二层 | **计算量——FLOPs** | 前向、训练、prefill、decode 各需要多少次运算？随 B/T/L/d 怎么增长？         | ✅ 已完成 |

> 运行性能（吞吐/时延/MFU）、系统瓶颈（compute-bound vs memory-bound）、分布式代价（DP/TP/PP）→ 见 大模型系统性能优化

## 0. 统一符号

| 符号 | 含义 |
|------|------|
| $V$ | vocab size |
| $d$ | hidden size |
| $L$ | Transformer block 层数 |
| $d_{\text{ff}}$ | FFN 中间维度 |
| $T$ | 序列长度（训练/推理时含义略有不同） |
| $T_0$ | 推理 prompt 长度 |
| $h$ | attention head 数 |
| $d_h$ | 每 head 维度，$d = h \cdot d_h$ |
| $B$ | batch size |
| $N$ | decode 阶段新生成 token 数 |
| $P$ | 模型总参数量 |
| $b_w, b_g, b_a, b_{kv}$ | 参数/梯度/激活/KV cache 每元素字节数 |

精度对应字节数：fp32 → 4B，fp16/bf16 → 2B，int8 → 1B，int4 → 0.5B。

> [!tip] 核心原则
> - **参数量** = 元素个数（与 $B, T$ 无关）
> - **FLOPs** = 矩阵乘法中的乘加次数（随 $B, T, L, d$ 变化）
> - **显存** = 元素个数 × 每元素字节数

## 第一层：模型本体——参数量计算

### 1. Embedding 层

Token embedding：每个 token 对应一个 $d$ 维向量，共 $V$ 个：

$$P_{\text{token\_emb}} = V \cdot d$$

Position embedding 仅在**可学习位置编码**时存在（最大长度 $T$）：

$$P_{\text{pos\_emb}} = T \cdot d$$

若使用 [位置编码](%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81.md)（RoPE / 正弦编码 / ALiBi），则此项 ≈ 0。Embedding 总计：

$$P_{\text{emb}} = Vd \quad (\text{无可学习位置编码})$$

### 2. Transformer Block

一个 block 由 Self-Attention + FFN + Norm 组成。

**Self-Attention**：四个线性层 $W_Q, W_K, W_V, W_O \in \mathbb{R}^{d \times d}$：

$$P_{\text{attn}} = 4d^2$$

**FFN**（标准版，两层线性 $d \to d_{\text{ff}} \to d$）：

$$P_{\text{ffn}} = 2d \cdot d_{\text{ff}}$$

取经典设定 $d_{\text{ff}} = 4d$ 时：

$$P_{\text{ffn}} = 8d^2$$

**Norm**：每层两个 LayerNorm（scale + bias）= $4d$，或 RMSNorm（仅 scale）= $2d$。相对于 $d^2$ 是小项，手算时常忽略。

单层 block 总计（忽略 norm）：

$$P_{\text{block}} \approx 4d^2 + 2dd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时得到最常用的近似：

$$P_{\text{block}} \approx 12d^2$$

$L$ 层合计：

$$P_{\text{blocks}} \approx L(4d^2 + 2dd_{\text{ff}}) \approx 12Ld^2$$

### 3. LM Head

将 hidden state 映射回 vocab logits：

$$P_{\text{lm\_head}} = d \cdot V$$

> [!note] 权重共享（Weight Tying）
> 很多语言模型让 lm head 与 token embedding 共享权重：$W_{\text{lm\_head}} = W_{\text{token\_emb}}^\top$。此时 lm head 不新增参数，$P_{\text{lm\_head}} = 0$（额外新增）。

### 4. 总参数量汇总

不共享 lm head + 可学习位置编码：

$$P_{\text{total}} = (Vd + Td) + L(4d^2 + 2dd_{\text{ff}}) + dV$$

常见近似（不算位置编码和 norm）：

$$P_{\text{total}} \approx 2Vd + L(4d^2 + 2dd_{\text{ff}})$$

$d_{\text{ff}} = 4d$ 时：

$$P_{\text{total}} \approx 2Vd + 12Ld^2$$

若 lm head 与 embedding 共享：

$$P_{\text{total}} \approx Vd + 12Ld^2$$

### 5. 现代变体对参数量的影响

| 变体           | 影响           | 参数量变化                                           |
| ------------ | ------------ | ----------------------------------------------- |
| SwiGLU / GLU | FFN 多一个门控投影  | $2dd_{\text{ff}} \to \frac{8}{3}dd_{\text{ff}}$ |
| GQA / MQA    | K/V head 数减少 | K/V 投影参数 < $d^2$                                |

> [!warning] head 数 $h$ 的作用
> 在标准 MHA 中，$h$ 影响内部计算过程但**不改变总参数量**——Q/K/V/O 仍然是 $d \to d$ 的映射。GQA/MQA 下除外。

## 第二层：计算量——FLOPs 推导与时间计算

> [!tip] FLOPs 计数约定：
> $(m,n) \times (n,p) \to (p,m)$ 的矩阵乘法记为 $2mnp$ FLOPs（含乘法和加法）。
> 
> 以下统计**主干 FLOPs**（大矩阵乘法），忽略 embedding 查表、softmax、Norm、激活函数等小项。

### 1. 单层 block 前向 FLOPs

输入 $X \in \mathbb{R}^{B \times T \times d}$。

**Q/K/V/O 四个线性层**：每个是 $(B,T,d) \times (d,d)$，单个 $2BTd^2$，四个合计：

$$F_{QKVO} = 8BTd^2$$

**Attention 分数矩阵** $QK^\top \in \mathbb{R}^{T \times T}$，每元素为长度 $d$ 的点积：

$$F_{QK^\top} = 2BT^2d$$

**Attention 输出** $\text{scores} \times V$：$(T,T) \times (T,d) \to (T,d)$：

$$F_{\text{attn} \cdot V} = 2BT^2d$$

Attention 主体两步合计：$F_{\text{attn-main}} = 4BT^2d$

**FFN 两层**：上投影 $(B,T,d) \times (d,d_{\text{ff}})$ + 下投影 $(B,T,d_{\text{ff}}) \times (d_{\text{ff}},d)$：

$$F_{\text{FFN}} = 4BTdd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时：$F_{\text{FFN}} = 16BTd^2$

**单层 block 总计**：

$$F_{\text{block}} = 8BTd^2 + 4BT^2d + 4BTdd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时：

$$\boxed{F_{\text{block}} = 24BTd^2 + 4BT^2d}$$

### 2. 整模型一次前向

$L$ 层 blocks + lm head $(B,T,d) \times (d,V)$：

$$F_{\text{fwd}} \approx L(8BTd^2 + 4BT^2d + 4BTdd_{\text{ff}}) + 2BTdV$$

$d_{\text{ff}} = 4d$ 时：

$$\boxed{F_{\text{fwd}} \approx L(24BTd^2 + 4BT^2d) + 2BTdV}$$

### 3. 训练 FLOPs

反向传播包含前向 + 对输入梯度 + 对权重梯度，粗略近似：

$$\boxed{F_{\text{train}} \approx 3 F_{\text{fwd}}}$$

即：

$$F_{\text{train}} \approx L(72BTd^2 + 12BT^2d) + 6BTdV$$

### 4. 推理 FLOPs：Prefill 与 Decode 分离与时间计算

推理必须分两段处理，因为计算形式不同。

> [!tip] prefill and decode 瓶颈
> prefill的瓶颈主要在计算量上，所以时间是这部分的FLOPs/机器的参数
> 而Decode的时间瓶颈主要在带宽上，所以这部分主要是KV cache/带宽。

#### 4.1 Prefill

Prompt 长度为 $T_0$，本质是一次完整前向并建立 [KV Cache](KV%20Cache.md)：

$$F_{\text{prefill}} \approx L(24BT_0d^2 + 4BT_0^2d) + 2BT_0dV$$

attention 仍含 $T_0^2$ 平方项。

#### 4.2 Decode 单步

当前上下文长度 $T$，生成 1 个新 token。输入形状退化为 $(B, 1, d)$，但需与历史 KV cache 交互。

- Q/K/V/O 四个线性层：$8Bd^2$
- Attention（当前 Q 与历史 K/V 匹配）：$4BTd$（不再是 $T^2d$）
- FFN：$4Bdd_{\text{ff}}$

单层 decode-step：

$$F_{\text{block, decode-step}} = 8Bd^2 + 4BTd + 4Bdd_{\text{ff}}$$

整模型单步（含 lm head）：

$$\boxed{F_{\text{decode-step}} \approx L(8Bd^2 + 4BTd + 4Bdd_{\text{ff}}) + 2BdV}$$

> [!tip] KV cache 的关键作用
> 将 decode 阶段的 attention 从 $O(T^2)$ 降到 $O(T)$。历史 K/V 不必重算，只需缓存复用。

#### 4.3 连续生成 N 个 token

第 $i$ 步上下文长度 $T_i = T_0 + i - 1$，总 decode FLOPs：

$$F_{\text{decode,total}} \approx BLN(8d^2 + 4dd_{\text{ff}}) + 4BLd \sum_{i=1}^{N} T_i + 2BNdV$$

其中 $\sum_{i=1}^{N} T_i = NT_0 + \frac{N(N-1)}{2}$。

完整推理总 FLOPs：

$$F_{\text{infer}} = F_{\text{prefill}} + F_{\text{decode,total}}$$

### 5. Scaling 规律总结

从单层公式 $F_{\text{block}} = 24BTd^2 + 4BT^2d$ 出发：

| 变量 | 增长阶 | 说明 |
|------|--------|------|
| $B$（batch size） | $O(B)$ | 线性 |
| $L$（层数） | $O(L)$ | 线性 |
| $d$（hidden size） | $O(d^2)$ 主导 | QKV/O 和 FFN 为平方项；attention 对 $d$ 本身是线性 |
| $T$（序列长度） | $O(T) + O(T^2)$ | QKV/FFN 为线性；**attention 为平方** |

Decode 阶段 attention 降为 $O(T)$（感谢 KV cache），这是长上下文推理的核心瓶颈所在。

## 第三层：显存占用

分两条线分析：**训练**（参数 + 梯度 + 优化器 + 激活）和**推理**（权重 + [KV Cache](KV%20Cache.md) + 运行时 buffer）。

$$M_{\text{train}} = M_{\text{param}} + M_{\text{grad}} + M_{\text{opt}} + M_{\text{act}}$$

$$M_{\text{infer}} = M_{\text{param}} + M_{\text{KV}} + M_{\text{runtime}}$$

### 1. 参数显存

$$M_{\text{param}} = P \cdot b_w$$

例：7B 模型 bf16 → $7 \times 10^9 \times 2 \approx 14$ GB。

### 2. 梯度显存

每个参数对应一个梯度：

$$M_{\text{grad}} = P \cdot b_g$$

通常与参数同量级（bf16 梯度 → $2P$）。

### 3. Optimizer State 显存

以 Adam/AdamW 为例，需保存一阶动量 $m$ 和二阶动量 $v$（均与参数同形，fp32 存储）：

$$M_{\text{opt}} \approx 8P \quad (\text{仅 } m, v)$$

混合精度训练若额外维护 fp32 master weights：

$$M_{\text{opt}} \approx 12P \quad (+ \text{master weights})$$

**常见训练总账**（bf16 参数 + bf16 梯度 + AdamW + fp32 master）：

| 分项 | 占用 |
|------|------|
| 参数 | $2P$ |
| 梯度 | $2P$ |
| 优化器状态 | $12P$ |
| **合计** | **$\approx 16P$** |

这就是 Adam 训练显存消耗大的根本原因。

### 4. Activation 显存

训练时反向传播需要保留前向中间结果，这是最容易爆的部分。

粗略估计：每层产生若干 $(B,T,d)$ 形状的中间张量，总计：

$$M_{\text{act}} \approx c \cdot BTLd \cdot b_a$$

$c$ 为实现相关常数（不同框架、是否 checkpoint、是否 [Flash Attention](Flash%20Attention.md) 均会影响）。

> [!warning] 为什么 activation 容易爆
> 参数显存固定为 $P$ 的函数，但 activation 随 $B$、$T$、$L$、$d$ 一起增长。很多时候不是模型装不下，而是 **batch 一大就爆、sequence 一长就爆**——爆的是 activation。

**Naive attention 的额外开销**：如果显式保存 attention score 矩阵 $(B, h, T, T)$，会多出：

$$M_{\text{attn-map}} \approx B \cdot h \cdot T^2 \cdot b_a$$

这一项随 $T^2$ 增长，长序列下非常可怕。[Flash Attention](Flash%20Attention.md) 的核心价值之一就是不物化完整的 $T \times T$ attention 矩阵，显著降低此开销。

**Gradient Checkpointing**：前向少存激活，反向时重算中间结果——典型的**用算力换显存**策略。

#### 符号定义

```
b  = batch size
s  = sequence length
h  = hidden dimension
a  = attention heads
```

#### Self-Attention 部分

每一步的输出张量都要缓存用于计算梯度：

|操作|保存的张量|显存（bytes）|
|---|---|---|
|LayerNorm 输入 x|(b, s, h)|2bsh|
|Q, K, V 投影后|(b, s, h) ×3|6bsh|
|Attention Score QKᵀ/√d|(b, a, s, s)|2bas²|
|Softmax 输出 P|(b, a, s, s)|2bas²|
|Dropout mask|(b, a, s, s)|bas²（bool）|
|Attention Output PV|(b, s, h)|2bsh|
|输出投影后|(b, s, h)|2bsh|

**Attention 小计：**

```
≈ 10bsh + 5bas²
```

#### FFN 部分

|操作|保存的张量|显存（bytes）|
|---|---|---|
|LayerNorm 输入|(b, s, h)|2bsh|
|第一个线性层输出|(b, s, 4h)|8bsh|
|GeLU/SiLU 激活输出|(b, s, 4h)|8bsh|
|第二个线性层输出|(b, s, h)|2bsh|

**FFN 小计：**

```
≈ 20bsh
```

#### 单层合计

```
per_layer = 2 × (30bsh + 5bas²)
          = 60bsh + 10bas²  bytes
```

> [!warning] 易错点
这就是 ZeRO 论文那个公式的来源：`s × b × h × (34 + 5as/h)`，系数略有差异是因为论文用 Post-LN 结构并忽略了部分小项。

#### 7B 数值代入（b=1, s=2048, h=4096, a=32, L=32）
```
线性项：60 × 1 × 2048 × 4096 = 503 MB / layer
Attn Score 项：10 × 1 × 32 × 2048² = 1342 MB / layer

单层激活 ≈ 1.8 GB
32 层合计 ≈ 57 GB（不用 checkpointing）
```

注意 attention score 项是 **s 的平方**，长序列时会爆炸：

```
s=2048 → 8.6 GB（仅 attn score，32 层）
s=4096 → 34 GB（4 倍增长）
```
### 5. KV Cache 显存（推理核心）

标准 MHA 下，每个 token 在每层缓存一个 Key 和一个 Value 向量（各 $d$ 维）：

$\boxed{M_{\text{KV}} = 2BLTd \cdot b_{kv}}$

fp16/bf16 时：$M_{\text{KV}} = 4BLTd$ Byte。

[MHA变体：MQA与GQA](MHA%E5%8F%98%E4%BD%93%EF%BC%9AMQA%E4%B8%8EGQA.md) 下，KV head 数 $n_{\text{kv}} < h$：

$M_{\text{KV}} = 2BLT \cdot n_{\text{kv}} d_h \cdot b_{kv}$

KV cache 随推理过程持续增长（每生成一个 token，$T$ 加 1），这也是长上下文推理和高并发推理吃显存的主因。

### 6. 显存小结

| 场景  | 主要组成                           | 主导项                              |
| --- | ------------------------------ | -------------------------------- |
| 训练  | 参数 + 梯度 + 优化器 + 激活             | 小模型→优化器状态；大 batch/长序列→activation |
| 推理  | 权重 + KV cache + runtime buffer | 模型权重 + KV cache                  |

最该记住的五个公式：

$$
\begin{aligned}
M_{\text{param}} &= P \cdot b_w \\
M_{\text{grad}} &= P \cdot b_g \\
M_{\text{opt}} &\approx 8P \sim 12P \\
M_{\text{act}} &\approx c \cdot BTLd \cdot b_a \\
M_{\text{KV}} &= 2BLTd \cdot b_{kv} \\
\end{aligned}
$$

> - **AdamW 优化器状态约 12P（含 master weights）**，远大于参数本身（2P），是训练显存的大头

## 四、激活值的两大救星

### Gradient Checkpointing

不保存所有层的激活值，只在 checkpoint 位置保存，反向传播时重新跑前向还原：

```
全保存：  32 × 1.8 GB = 57 GB
每层 checkpoint：只保存层边界输入 x = 32 × 16 MB ≈ 0.5 GB
代价：多算一次前向，训练时间增加约 30-40%
```

### Flash Attention

改变 attention score 的存储方式：

```
普通 Attention：保存完整 (b, a, s, s) 矩阵 → O(s²) 显存
Flash Attention：分块计算，只保存 log-sum-exp 统计量 → O(s) 显存

消除 attn score 项后（7B）：
  单层激活 ≈ 503 MB → 32 层 ≈ 16 GB

Flash Attention + Gradient Checkpointing 叠加：
  激活值降到 1-3 GB，代价仅 30% 计算时间
```

**这也解释了为什么工程实践中 ZeRO 的 16 bytes 估算"够用"**——现代训练栈默认开这两个优化，激活值可以忽略，16 bytes 的误差范围能覆盖它。长序列不开 Flash Attention 时例外。

---

## 五、把激活值纳入统一公式

为了和 16 bytes 公式统一，把激活值也表达成「每参数 α bytes」的形式。

每层参数量约为 `Φ ≈ L × 12h²`，激活值总量为 `A = L × bsh(60 + 10as/h)`，因此：

```
α = A / Φ = (bs/h) × (5 + 5as/6h)

Total Memory = Φ × (16 + α)  bytes
```

**7B 代入验证：**

```
α = (1 × 2048 / 4096) × (5 + 5 × 32 × 2048 / 24576)
  = 0.5 × (5 + 13.65) ≈ 9.3 bytes/param

激活显存验证：7B × 9.3 ≈ 65 GB（与直接算的 57 GB 量级吻合）
总显存：7B × (16 + 9.3) ≈ 177 GB
```

**不同配置下的 α 修正：**

|配置|α 近似值（7B，b=1，s=2048）|
|---|---|
|无优化|~9.3|
|Flash Attention|~2.5（消除 s² 项）|
|Grad Checkpointing|~0.05|
|两者叠加|~0.01（退化回 16 bytes 公式）|

## 六、冻结层训练的显存计算

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%85%AD%E5%86%BB%E7%BB%93%E5%B1%82%E8%AE%AD%E7%BB%83%E7%9A%84%E6%98%BE%E5%AD%98%E8%AE%A1%E7%AE%97)

冻结层意味着不需要计算参数梯度，不需要优化器状态，但参数本身仍在显存中：

```
冻结层：只保留 fp16 参数 → 2 bytes/param
训练层：保留完整训练状态 → 16 bytes/param
```

**7B 冻结 50%（3.5B 参数）：**

```
冻结层显存 = 3.5B × 2  =  7 GB
训练层显存 = 3.5B × 16 = 56 GB
Model States 合计 = 63 GB（相比 112 GB 节省约 44%）
```

### ⚠️ 激活值的特殊情况

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%EF%B8%8F-%E6%BF%80%E6%B4%BB%E5%80%BC%E7%9A%84%E7%89%B9%E6%AE%8A%E6%83%85%E5%86%B5)

冻结层虽然不需要参数梯度，但如果训练层在冻结层之后，反向传播仍需穿越冻结层计算**激活梯度**：

```
冻结前半部分层（底层）→ 反向仍需穿越 → 激活值显存几乎不减少
冻结后半部分层（顶层）→ 反向不经过  → 激活值可以节省
```

## 七、LoRA 训练显存计算

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E4%B8%83lora-%E8%AE%AD%E7%BB%83%E6%98%BE%E5%AD%98%E8%AE%A1%E7%AE%97)

LoRA 核心：冻结原始权重 W，只训练低秩矩阵 A 和 B：

```
ΔW = B × A，  A ∈ R^{d×r}，B ∈ R^{r×k}，r << d,k
```

### LoRA 参数量

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#lora-%E5%8F%82%E6%95%B0%E9%87%8F)

以 7B 模型（h=4096，L=32，r=8，作用于 Q/K/V/O）：

```
每层 LoRA 参数：4 × (4096×8 + 8×4096) = 4 × 65536 ≈ 0.26M
32 层合计 ≈ 8M（约为 7B 的 0.1%）
```

实际上视具体实现也常在 25M 上下，这里取保守值。

### 显存构成

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E6%98%BE%E5%AD%98%E6%9E%84%E6%88%90)

```
原始模型权重（冻结，fp16）：7B × 2    = 14 GB
LoRA 参数（fp16）：         25M × 2   ≈  0.05 GB
LoRA 梯度（fp16）：         25M × 2   ≈  0.05 GB
LoRA 优化器状态（fp32）：   25M × 12  ≈  0.3 GB
```

### ⚠️ LoRA 激活值的常见误解

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%EF%B8%8F-lora-%E6%BF%80%E6%B4%BB%E5%80%BC%E7%9A%84%E5%B8%B8%E8%A7%81%E8%AF%AF%E8%A7%A3)

反向传播仍然需要穿越所有冻结层来计算 LoRA 分支的梯度，**激活值显存并不会减少**：

```
LoRA 不用 gradient checkpointing：
  14 GB + 0.4 GB + 30 GB（激活）≈ 44 GB

LoRA + gradient checkpointing：
  14 GB + 0.4 GB + 3 GB ≈ 17-18 GB  ✅ 单张 A100 80G 可以跑
```

**LoRA 最大的节省来自优化器状态（84 GB → 0.3 GB），而不是激活值。激活值是 LoRA 最容易被忽视的大头。**

### 三种训练方式汇总（7B）

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E4%B8%89%E7%A7%8D%E8%AE%AD%E7%BB%83%E6%96%B9%E5%BC%8F%E6%B1%87%E6%80%BB7b)

|训练方式|参数显存|梯度+优化器|激活值|总计（约）|
|---|---|---|---|---|
|全量训练|14 GB|98 GB|30 GB|~144 GB|
|冻结后 50% 层|14 GB|49 GB|~25 GB|~88 GB|
|LoRA (r=8)|14 GB|0.4 GB|30 GB|~44 GB|
|LoRA + GradCkpt|14 GB|0.4 GB|3 GB|**~18 GB**|

## 八、DataLoader 对显存的影响

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%85%ABdataloader-%E5%AF%B9%E6%98%BE%E5%AD%98%E7%9A%84%E5%BD%B1%E5%93%8D)

### 结论先行

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E7%BB%93%E8%AE%BA%E5%85%88%E8%A1%8C)

**DataLoader 本身对 GPU 显存的影响可以忽略。**

DataLoader 的 prefetch 和 batch 主要占用 CPU RAM，只有 `.to(device)` 之后才转移到 GPU 显存，而 token 是离散整数，远比 fp16 激活值小：

```
单个 batch 输入显存：
  input_ids:       b × s × 4 bytes
  attention_mask:  b × s × 1 bytes
  labels:          b × s × 4 bytes
  合计 ≈ b × s × 13 bytes

b=32, s=4096：32 × 4096 × 13 ≈ 1.6 MB  ← 可以忽略
```

### 真正需要关注的：显存 Spike

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E7%9C%9F%E6%AD%A3%E9%9C%80%E8%A6%81%E5%85%B3%E6%B3%A8%E7%9A%84%E6%98%BE%E5%AD%98-spike)

实际工程中 OOM 往往不是平均占用超了，而是**瞬间峰值**超了。

**Vocab Logits 是最容易被忽视的 spike：**

```
Logits tensor shape：(b, s, vocab_size)

现代 LLM vocab 越来越大：
  LLaMA-2:  32,000
  LLaMA-3:  128,256  ← 4 倍于 LLaMA-2
  Qwen2:    152,064

LLaMA-3，b=4，s=4096，fp32：
  4 × 4096 × 128256 × 4 bytes ≈ 8.4 GB  ← 相当可观，必须显式计算
```

其他 spike 来源：

- Forward 结束、Backward 开始前：激活值 + 当前层梯度同时存在，峰值约为激活值的 1.5x
- Optimizer step 时：fp32 参数副本更新完，旧的还没释放，短暂双份参数
- CUDA 显存碎片化（fragmentation）：PyTorch 的 caching allocator 持有已释放的显存块，实测可导致额外 5-10% 的"账面占用"，可通过 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 缓解

### 完整估算模板

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%AE%8C%E6%95%B4%E4%BC%B0%E7%AE%97%E6%A8%A1%E6%9D%BF)

```python
def total_memory_estimate(phi_B, b, s, h, a, layers, vocab_size,
                           use_flash=True, use_ckpt=True):
    # Model States
    model_states = phi_B * 1e9 * 16

    # Activation
    if use_flash and use_ckpt:
        activation = 0
    elif use_flash:
        activation = layers * 60 * b * s * h * 2
    else:
        activation = layers * (60*b*s*h + 10*b*a*s*s) * 2

    # Logits spike（不能忽略！）
    logits = b * s * vocab_size * 4

    # Safety buffer 10%
    subtotal = model_states + activation + logits
    return subtotal * 1.1 / 1024**3

# LLaMA-3 7B, b=2, s=4096
# ≈ (112 GB + 0 + 4.2 GB) × 1.1 ≈ 127 GB
```

### 显存预留系数建议

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E6%98%BE%E5%AD%98%E9%A2%84%E7%95%99%E7%B3%BB%E6%95%B0%E5%BB%BA%E8%AE%AE)

|场景|额外预留|说明|
|---|---|---|
|文本 LLM 训练|+10%|主要 cover spike 和 CUDA context|
|大 vocab（>100K）|+10% + Logits 显式计算|LLaMA-3/Qwen 必须单独算|
|多模态训练|+15~20%|图像/视频 feature 更大|
|长序列（s>8K）|+15%|attention 计算中间态 spike|
|梯度累积步数>1|不额外增加|每步 batch 大小不变|

## 九、MoE 模型训练显存：以 Qwen3-30B-A3B 为例

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E4%B9%9Dmoe-%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E6%98%BE%E5%AD%98%E4%BB%A5-qwen3-30b-a3b-%E4%B8%BA%E4%BE%8B)

### MoE 的核心陷阱

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#moe-%E7%9A%84%E6%A0%B8%E5%BF%83%E9%99%B7%E9%98%B1)

Dense 模型：`Φ_active = Φ_total`，直接用 `16 × Φ_total` 估算。

MoE 打破了这个等式：

```
Qwen3-30B-A3B：
  Φ_total  = 30B（所有专家都要加载进显存）
  Φ_active =  3B（每个 token 只激活这么多参数）
```

**但训练时，所有 30B 的梯度和优化器状态都必须存在。**

因为 routed expert 的权重在不同 step 被不同 token 激活，每个专家都需要积累梯度和维护完整的优化器状态（m, v），否则某个专家某一步没被激活，它的 m/v 就丢失了。

### Qwen3-30B-A3B 架构参数

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#qwen3-30b-a3b-%E6%9E%B6%E6%9E%84%E5%8F%82%E6%95%B0)

```
num_hidden_layers    = 48
hidden_size (h)      = 2048
num_attention_heads  = 32，head_dim = 128
num_key_value_heads  = 8   (GQA)
ffn_dim_per_expert   = 1024
num_experts          = 128
num_experts_per_tok  = 8   (top-8 routing)
shared_experts       = 1   (每层永远激活，dim=4096)
vocab_size           = 151,936
```

**参数量验证：**

```
Attention per layer（GQA）：
  Q：2048×2048 = 4.2M
  KV：2048×2048 = 4.2M（GQA 极大减少 KV 参数）
  O：4.2M
  ≈ 12M / layer

Routed Expert FFN per layer：
  128 experts × (2048×1024 + 1024×2048) × 2 ≈ 512M / layer

Shared Expert per layer：
  (2048×4096 + 4096×2048) × 2 = 32M / layer

48 层 + Embedding：
  48 × (12+512+32)M + 1.2B ≈ 27.4B ≈ 30B ✓

Active params 验证（per token）：
  12M（attn）+ 8×4M（top-8 experts）+ 32M（shared）= 76M / layer
  48 layers：76M × 48 ≈ 3.65B ≈ 3B（A3B 得名于此）✓
```

### Model States：按 Φ_total 计算

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#model-states%E6%8C%89-%CF%86_total-%E8%AE%A1%E7%AE%97)

```
全量训练（混合精度 + Adam）：
  Model States = 30B × 16 bytes = 480 GB

⚠️ 用 Φ_active = 3B 估算是严重错误，会低估 10 倍
```

### 激活值：按 Active 路径计算

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E6%BF%80%E6%B4%BB%E5%80%BC%E6%8C%89-active-%E8%B7%AF%E5%BE%84%E8%AE%A1%E7%AE%97)

这是 MoE 真正享受 sparsity 红利的地方。

**Attention 激活（GQA 下）：**

```
Flash Attention 开启时，per layer：
  ≈ 60bsh = 60 × 1 × 2048 × 2048 = 251 MB
（GQA 的 kv_heads=8 远小于 32，attn score 项本来就小）
```

**Expert FFN 激活（关键差异）：**

```
Router logits：(b, s, num_experts) = 1 × 2048 × 128 × 2 = 0.5 MB
Gate scores：  (b, s, top_k) = 1 × 2048 × 8 × 4 = 0.064 MB

Routed Expert 中间激活（只算 8 个 expert）：
  b × s × top_k × ffn_dim × 2 × 2 = 1 × 2048 × 8 × 1024 × 4 = 64 MB

Shared Expert 中间激活：
  b × s × 4096 × 4 = 32 MB

Expert FFN 合计 ≈ 96 MB / layer
```

**单层激活：**

```
251 MB（attention）+ 96 MB（MoE FFN）= 347 MB

48 层合计：347 × 48 ≈ 16.7 GB
```

对比同等 active 参数量的 Dense 3B 模型激活值（约 10-15 GB），MoE 和它相近，这符合直觉：激活值只跟计算路径有关。

### MoE 特有的额外显存开销

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#moe-%E7%89%B9%E6%9C%89%E7%9A%84%E9%A2%9D%E5%A4%96%E6%98%BE%E5%AD%98%E5%BC%80%E9%94%80)

**Expert Parallelism（EP）通信缓冲区：**

MoE 训练通常使用 EP，不同 GPU 持有不同专家，需要 All-to-All 通信：

```
EP=8（每 GPU 持有 128/8=16 个专家），b=1, s=2048, top_k=8：
  capacity_per_rank = 1 × 2048 × 8 / 8 = 2048 tokens
  buffer = 8 × 2048 × 2048 × 2 bytes × 2（双向）≈ 256 MB
```

**Auxiliary Load Balance Loss：**

```
Router probability per layer：(b, s, num_experts) fp32 = 1 MB / layer
48 层合计 ≈ 48 MB（可忽略）
```

### 完整显存汇总（b=1, s=2048, Flash Attn，无 GradCkpt）

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%AE%8C%E6%95%B4%E6%98%BE%E5%AD%98%E6%B1%87%E6%80%BBb1-s2048-flash-attn%E6%97%A0-gradckpt)

```
① Model States（Φ_total = 30B）：  480 GB
② 激活值（active 路径）：           16.7 GB
③ Logits spike：                    1 × 2048 × 151936 × 4 ≈ 1.2 GB
④ EP 通信缓冲区：                   ≈ 0.3 GB
⑤ CUDA Context + 碎片：            ≈ 2 GB

小计：≈ 500 GB
× 1.10 安全系数 ≈ 550 GB
```

### 与 Dense 30B 对比

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E4%B8%8E-dense-30b-%E5%AF%B9%E6%AF%94)

```
Dense 30B：
  Model States：480 GB
  激活值（h=7168，32 layers）：≈ 50-80 GB
  合计：≈ 560 GB

MoE 30B-A3B：
  Model States：480 GB（相同！）
  激活值：≈ 17 GB（远小于 Dense）
  合计：≈ 500 GB
```

**MoE 的节省完全体现在激活值上，Model States 按 Φ_total 算，不因 sparsity 减少。**

### 实际训练并行策略（8×H100 80GB = 640GB）

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%AE%9E%E9%99%85%E8%AE%AD%E7%BB%83%E5%B9%B6%E8%A1%8C%E7%AD%96%E7%95%A58h100-80gb--640gb)

```
ZeRO-3 切分 Model States：
  480 GB / 8 = 60 GB / GPU

Flash Attention + Grad Checkpointing：
  激活值：17 GB → ~2 GB

EP=8 通信 buffer：~0.3 GB

单卡实际占用：
  60 + 2 + 0.3 ≈ 62 GB  ✅  单张 H100 80GB 可以训练！

仅用 EP=8，不用 ZeRO-3：
  480 GB 无法切分 → 直接 OOM
```

## 十、统一估算公式总结

[](https://github.com/pengyanai/notebook/blob/gh-pages/posts/2026-02-26-llm-training-memory-estimation.md#%E5%8D%81%E7%BB%9F%E4%B8%80%E4%BC%B0%E7%AE%97%E5%85%AC%E5%BC%8F%E6%80%BB%E7%BB%93)

综合所有章节，完整的训练显存估算公式为：

```
Total = 16 × Φ_total               ← Model States，永远用总参数量
      + α × Φ_active               ← 激活值，按 active 路径
      + b × s × vocab_size × 4     ← Logits spike，显式计算
      + EP_buffer                  ← MoE 专用，约 0.3 GB
      + 1 GB                       ← CUDA Context 固定开销
      × 1.10 ~ 1.15                ← 安全系数（碎片化 + spike）

其中 α：
  无优化：             ~9.3 bytes/param（7B，s=2048）
  Flash Attention：    ~2.5
  Grad Checkpointing： ~0.05
  两者叠加：           ~0.01（可忽略，退化回 16 bytes）
```

对于 MoE，激活值系数还需加入 router overhead：

```
α_moe ≈ α_dense × 1.15（router 带来约 15% 额外激活开销）
```

**核心结论一句话：用 Φ_total 算 Model States，用 active 路径算激活值，别忘了 Logits spike，留 10% 安全余量。**

1. 计算kv cache
```
KV cache size per token=2×num_kv_heads×head_dim×bytes_per_elem*layers*B*S
					   = 2*4*128*2*48*128*11000
					   = 135GB
其中prefill 120GB
decode 1k: 15GB左右
```



1. 计算模型参数大小和激活大小
```
模型参数大小 = Attn+FFN+embedding+tokenizer
atten = Q+K+V+O

Q = O = hidden_size * num_attention_heads * head_dim
K = V = hidden_size * num_key_value_heads * head_dim
```
