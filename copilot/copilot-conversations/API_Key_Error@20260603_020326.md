# 1.5 - Scaling Law

这是OpenAI提出的概念。对于仅解码（decode-only）模型，其最终性能主要与以下三个因素相关：
-   计算量 $C$
-   模型参数量 $N$
-   数据大小 $D$ (通常指训练token数量)

模型的具体结构与此关系不大。

## Scaling Law 公式

$C = 6ND$

## 计算量、数据、模型的关系推导

### 1. 模型参数量 $N$

通常，前馈网络的维度 $d_{ff}$ 与模型维度 $d$ 的关系为：
$d_{ff} = 4d$

一个Transformer层（Decoder层）包含自注意力（Self-Attention）和多层感知机（MLP）两部分。

-   **自注意力部分**：
    包含Q、K、V、O的线性投影层。假设每个线性层参数量为 $d \times d$，则Q, K, V, O 四个线性层总参数量为 $4d^2$。

-   **MLP部分**：
    包含两个线性层，一个从 $d$ 升维到 $d_{ff}$，另一个从 $d_{ff}$ 降维到 $d$。
    参数量为 $d \times d_{ff} + d_{ff} \times d = 2 \times d \times d_{ff}$。
    代入 $d_{ff} = 4d$，则MLP部分的参数量为 $2 \times d \times 4d = 8d^2$。

因此，一个Transformer层（Decoder层）的总参数量约为：
$N_{layer} = 4d^2 + 8d^2 = 12d^2$

如果模型有 $L$ 层，则总模型参数量 $N \approx L \times 12d^2$。

### 2. 计算量 $C$

> 计算量的单位是FLOPs（floating point operations）。对于矩阵乘法 $A_{m \times n} \times B_{n \times p}$，相乘的计算量约为 $m \times n \times p$ 次乘法。通常一次加法和一次乘法算作2 FLOPs。

假设Decoder层的输入为 $B$ (batch size)，$S$ (序列长度)，$d$ (模型维度)。

-   **自注意力部分的计算 (近似乘法次数)**:
    -   输入线性层 (Q, K, V): $3 \times (B \times S \times d \times d)$
    -   Attention计算 ($Q K^T$): $B \times S \times S \times d$
    -   Score与V的计算 ($Attention \cdot V$): $B \times S \times S \times d$
    -   输出线性层 (O): $B \times S \times d \times d$

-   **MLP部分的计算 (近似乘法次数)**:
    -   升维: $B \times S \times d \times d_{ff}$
    -   降维: $B \times S \times d_{ff} \times d$

所以，整个Decoder层在正向传播中的计算量（近似乘法次数）为：
$$C_{layer\_forward} \approx 3BSd^2 + BS^2d + BS^2d + BSd^2 + BSd \cdot d_{ff} + BSd_{ff} \cdot d$$
$$C_{layer\_forward} \approx 4BSd^2 + 2BS^2d + 2BSd \cdot d_{ff}$$
代入 $d_{ff} = 4d$:
$$C_{layer\_forward} \approx 4BSd^2 + 2BS^2d + 2BSd \cdot 4d = 4BSd^2 + 2BS^2d + 8BSd^2 = 12BSd^2 + 2BS^2d$$

反向传播计算量是正向的2倍。所以，对于 $L$ 层模型，全部的计算量为：
$$C_{total} \approx 2 \times L \times (12BSd^2 + 2BS^2d)$$

根据经验法则和简化，平均每个token的计算量为：
$$C_{token} = 12d^2$$

所以对于全部包含 $D$ 个token的数据集，总计算量为：
$$C = D \times C_{token} = D \times 12d^2$$

# 1.6 - 集合通信与分布式算法

## 引言

在分布式系统中，尤其是大规模机器学习和深度学习训练中，多个计算节点（或进程）需要协同工作。为了实现高效的协同，节点之间的数据交换和同步至关重要。集合通信（Collective Communication）提供了一组原语，用于实现多个进程之间复杂的数据传输模式。而分布式通信算法则是实现这些集合通信操作的具体策略。

本讲义将详细介绍常见的集合通信操作及其背后的分布式通信算法。

---

## 一、集合通信操作 (Collective Communication Operations)

集合通信操作涉及通信组中的所有或部分进程，以协调的方式传输数据。

### 1. Broadcast (广播)

-   **描述**: 一个根进程（root process）将其数据发送给通信组中的所有其他进程。所有进程最终都拥有相同的数据副本。
-   **用途**: 分发模型参数、配置信息、超参数等。
-   **示意图**:
    ![[Broadcast_Diagram.png]]
    *(图示：进程0将数据发送给进程1, 2, 3)*

### 2. Scatter (分散)

-   **描述**: 一个根进程将其数据块（通常是一个数组）的不同部分发送给通信组中的不同进程。每个进程接收到数据的一个子集。
-   **用途**: 将一个大的数据集或模型参数矩阵分散到不同的工作进程进行并行处理。
-   **示意图**:
    ![[Scatter_Diagram.png]]
    *(图示：进程0将数据A, B, C, D分别发送给进程0, 1, 2, 3)*

### 3. Gather (收集)

-   **描述**: 通信组中的所有进程将其各自的数据发送给一个根进程。根进程将所有接收到的数据按顺序收集起来。
-   **用途**: 收集各个工作进程计算出的梯度、统计结果或部分处理的数据。
-   **示意图**:
    ![[Gather_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给进程0，进程0最终得到[A, B, C, D])*

### 4. Allgather (全收集)

-   **描述**: 类似于 Gather，但所有进程都作为根进程。每个进程将其数据发送给所有其他进程，最终所有进程都拥有通信组中所有进程的数据副本。
-   **用途**: 在每个进程都需要完整数据集或所有进程的中间结果时使用，例如在数据并行训练中，每个进程需要知道所有进程的梯度。
-   **示意图**:
    ![[Allgather_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给所有进程，所有进程最终都得到[A, B, C, D])*

### 5. Reduce (归约)

-   **描述**: 通信组中的所有进程将其数据发送给一个根进程，并在发送过程中对数据应用一个归约操作（如求和、求最大值、求最小值、逻辑与/或等）。根进程最终得到归约后的结果。
-   **用途**: 聚合所有进程的梯度（求和）、计算全局最大/最小值等。
-   **示意图**:
    ![[Reduce_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给进程0，并进行求和操作，进程0最终得到A+B+C+D)*

### 6. Allreduce (全归约)

-   **描述**: 类似于 Reduce，但所有进程都作为根进程。所有进程将其数据发送给所有其他进程，并应用归约操作，最终所有进程都得到相同的归约结果。
-   **用途**: 在数据并行训练中，计算所有进程的梯度总和，并将这个总和分发给所有进程，以便它们更新自己的模型副本。这是深度学习中最常用的集合通信操作之一。
-   **示意图**:
    ![[Allreduce_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给所有进程，并进行求和操作，所有进程最终都得到A+B+C+D)*

### 7. Reducescatter (归约分散)

-   **描述**: 结合了 Reduce 和 Scatter 的功能。所有进程贡献数据，对这些数据进行归约操作，然后将归约结果的不同部分分散到不同的进程。
-   **用途**: 通常作为 Allreduce 的一个阶段，特别是在 Ring-Allreduce 算法中。它可以有效地将一个大的归约结果分散到各个进程，每个进程只接收其负责的部分。
-   **示意图**:
    ![[Reducescatter_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别贡献数据A, B, C, D。进行归约操作后，将结果分成4份，分别发送给进程0, 1, 2, 3。例如，进程0得到归约结果的第一部分，进程1得到第二部分等。)*

## 二、分布式通信算法 (Distributed Communication Algorithms)

这些算法是实现上述集合通信操作的具体策略，它们决定了数据如何在网络中传输以达到最佳效率。

### 1. PS (Parameter Server) 算法

-   **描述**: Parameter Server 是一种经典的分布式训练架构。它将系统中的节点分为两类：
    -   **Parameter Servers (PS)**: 负责存储和更新模型参数。它们接收来自 Worker 的梯度，聚合后更新参数，并将新参数发送回 Worker。
    -   **Workers (工作节点)**: 负责计算模型在部分数据上的梯度。它们从 PS 获取最新参数，计算梯度，然后将梯度发送给 PS。
-   **工作流程**:
    1.  Worker 从 PS 拉取（pull）最新模型参数。
    2.  Worker 使用这些参数在本地数据上计算梯度。
    3.  Worker 将计算出的梯度推送（push）给 PS。
    4.  PS 接收到多个 Worker 的梯度后，进行聚合（例如求和），然后更新模型参数。
    5.  重复步骤1-4。
-   **优点**:
    -   架构简单，易于理解和实现。
    -   能够处理异构计算环境（不同性能的 Worker）。
    -   支持异步更新，提高训练吞吐量。
-   **缺点**:
    -   **参数服务器可能成为瓶颈**: 随着模型规模和 Worker 数量的增加，PS 的网络带宽和计算能力可能成为限制。
    -   **单点故障**: 如果 PS 发生故障，整个训练过程可能中断（尽管可以通过冗余 PS 解决）。
    -   **数据一致性问题**: 异步更新可能导致模型参数在不同 Worker 之间存在滞后，影响收敛性。
-   **示意图**:
    ![[Parameter_Server_Diagram.png]]
    *(图示：多个Worker与一个或多个Parameter Server进行参数和梯度交换)*

### 2. Halving and Doubling 算法

-   **描述**: 这是一类通用的、基于对数步数的通信模式，常用于实现 Allreduce、Broadcast 等操作。其核心思想是在每一步通信中，参与进程集合的大小减半（用于 Reduce 阶段）或数据量翻倍（用于 Broadcast/Allgather 阶段）。
-   **工作原理 (以 Allreduce 为例)**:
    1.  **Reduce 阶段 (Halving)**: 进程两两配对，交换数据并进行归约。在每一步中，通信距离减半，数据量保持不变，但每个进程持有的归约结果的“范围”扩大。经过 $\log_2 P$ 步（$P$ 为进程数），一个进程将拥有所有数据的归约结果。
    2.  **Broadcast 阶段 (Doubling)**: 拥有最终归约结果的进程将其结果广播给其他进程。同样通过两两配对的方式，在每一步中，拥有完整结果的进程数量翻倍。经过 $\log_2 P$ 步，所有进程都将拥有最终归约结果。
-   **优点**:
    -   通信步数少，通常为 $O(\log P)$。
    -   适用于中小型数据量和进程数。
-   **缺点**:
    -   对于大规模集群，可能存在中心化通信模式，导致网络拥塞。
    -   需要同步通信，等待所有进程完成当前步才能进入下一步。
-   **示意图**:
    ![[Halving_Doubling_Diagram.png]]
    *(图示：展示进程0-7如何通过对半交换和归约，最终所有进程都得到总和)*

### 3. Ring-Allreduce (环形全归约)

-   **描述**: Ring-Allreduce 是一种高效的去中心化 Allreduce 算法，广泛应用于现代深度学习框架（如 Horovod、NCCL）。它将所有进程组织成一个逻辑环，数据在环中顺时针或逆时针传递。
-   **工作原理**: Ring-Allreduce 分为两个主要阶段：
    1.  **Reduce-Scatter 阶段**:
        -   每个进程将其本地数据（例如梯度）分割成 $P$ 个块（$P$ 为进程数）。
        -   在 $P-1$ 步中，每个进程将其第 $i$ 块数据发送给其右邻居，并从其左邻居接收第 $i-1$ 块数据。
        -   同时，接收到的数据会与本地对应块的数据进行归约（例如求和）。
        -   经过 $P-1$ 步后，每个进程都将拥有所有进程贡献的、经过归约的、**不同**数据块的最终结果。
    2.  **Allgather 阶段**:
        -   在接下来的 $P-1$ 步中，每个进程将其在 Reduce-Scatter 阶段获得的归约结果块发送给其右邻居，并从其左邻居接收一个归约结果块。
        -   通过这种方式，每个进程逐步收集到所有归约后的数据块。
        -   经过 $P-1$ 步后，所有进程都将拥有完整的、经过归约的最终结果。
-   **优点**:
    -   **无中心瓶颈**: 数据在环中传递，没有单个节点成为瓶颈。
    -   **带宽最优**: 在理想情况下，通信带宽利用率高，每个进程只发送和接收一次完整的数据量。
    -   **可扩展性强**: 适用于大规模集群。
    -   **重叠计算与通信**: 可以通过将数据分块，实现通信与计算的重叠，进一步提高效率。
-   **缺点**:
    -   **延迟较高**: 对于小消息，由于需要 $2(P-1)$ 步通信，延迟可能高于树形结构算法。
    -   **实现复杂性**: 相对于 Parameter Server 架构，实现更复杂。
-   **示意图**:
    ![[Ring_Allreduce_Diagram.png]]
    *(图示：展示数据块如何在环形拓扑中传递，经过Reduce-Scatter和Allgather两个阶段，最终所有进程都得到完整的归约结果)*

## 总结

集合通信操作是构建高效分布式系统的基石，它们提供了抽象的数据传输模式。而 Parameter Server、Halving and Doubling 以及 Ring-Allreduce 等分布式通信算法则是实现这些操作的具体技术。在深度学习领域，Ring-Allreduce 因其优异的扩展性和带宽效率，已成为主流的 Allreduce 实现方式。理解这些概念对于设计和优化分布式训练系统至关重要。

-   **描述**: 一个根进程（root process）将其数据发送给通信组中的所有其他进程。所有进程最终都拥有相同的数据副本。

-   **用途**: 将一个大的数据集或模型参数矩阵分散到不同的工作进程进行并行处理。

-   **描述**: 类似于 Gather，但所有进程都作为根进程。每个进程将其数据发送给所有其他进程，最终所有进程都拥有通信组中所有进程的数据副本。

### 5. Reduce (归约)

-   **描述**: 通信组中的所有进程将其数据发送给一个根进程，并在发送过程中对数据应用一个归约操作（如求和、求最大值、求最小值、逻辑与/或等）。根进程最终得到归约后的结果。
-   **用途**: 聚合所有进程的梯度（求和）、计算全局最大/最小值等。
-   **示意图**:
    ![[Reduce_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给进程0，并进行求和操作，进程0最终得到A+B+C+D)*

### 6. Allreduce (全归约)

-   **描述**: 类似于 Reduce，但所有进程都作为根进程。所有进程将其数据发送给所有其他进程，并应用归约操作，最终所有进程都得到相同的归约结果。
-   **用途**: 在数据并行训练中，计算所有进程的梯度总和，并将这个总和分发给所有进程，以便它们更新自己的模型副本。这是深度学习中最常用的集合通信操作之一。
-   **示意图**:
    ![[Allreduce_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别将数据A, B, C, D发送给所有进程，并进行求和操作，所有进程最终都得到A+B+C+D)*

### 7. Reducescatter (归约分散)

-   **描述**: 结合了 Reduce 和 Scatter 的功能。所有进程贡献数据，对这些数据进行归约操作，然后将归约结果的不同部分分散到不同的进程。
-   **用途**: 通常作为 Allreduce 的一个阶段，特别是在 Ring-Allreduce 算法中。它可以有效地将一个大的归约结果分散到各个进程，每个进程只接收其负责的部分。
-   **示意图**:
    ![[Reducescatter_Diagram.png]]
    *(图示：进程0, 1, 2, 3分别贡献数据A, B, C, D。进行归约操作后，将结果分成4份，分别发送给进程0, 1, 2, 3。例如，进程0得到归约结果的第一部分，进程1得到第二部分等。)*

## 二、分布式通信算法 (Distributed Communication Algorithms)

这些算法是实现上述集合通信操作的具体策略，它们决定了数据如何在网络中传输以达到最佳效率。

### 1. PS 算法 (Parameter Server, 参数服务器)

-   **描述**: Parameter Server 是一种经典的分布式训练架构。它采用**中心化**的训练架构，将系统中的节点分为两类角色：
    -   **参数服务器 (Parameter Servers, PS)**: 负责存储和更新模型参数。它们接收来自 Worker 的梯度，聚合后更新参数，并将新参数发送回 Worker。
    -   **工作节点 (Workers)**: 负责计算模型在部分数据上的梯度。它们从 PS 获取最新参数，计算梯度，然后将梯度推送（push）给 PS 做累积 (Reduce)。
-   **工作流程**:
    1.  Worker 从 PS 拉取（pull）最新模型参数。
    2.  Worker 使用这些参数在本地数据上计算梯度。
    3.  Worker 将计算出的梯度推送（push）给 PS。
    4.  PS 接收到多个 Worker 的梯度后，进行聚合（例如求和），然后更新模型参数。
    5.  重复步骤1-4。
-   **缺点**:
    -   **木桶效应 (Straggler Problem)**: 每一轮的训练迭代都需要所有卡都将数据同步完成一次 Reduce 才算结束。并行的卡很多的时候，**本桶效应**就会很严重，一旦有一张卡速度较慢会拖慢整个集群的速度，导致计算效率低。
    -   **参数服务器可能成为瓶颈**: Reduce 服务器任务过重，成为瓶颈。所有的节点需要和 Reduce 进行数据、梯度和参数的通信，当模型较大或者数据量较大的时候，通信开销很大，根节点收到三重时数据，从而造成瓶颈。
-   **示意图**:
    ![[图 10.9: PS 算法示意图]]
    *(图 10.9: PS 算法示意图)*

### 2. Halving and Doubling (HD) 算法 (Recursive Doubling)

-   **描述**: 这是一类通用的、基于对数步数的通信模式，常用于实现 Allreduce、Broadcast 等操作。其核心思想是在每一步通信中，参与进程集合的大小减半（用于 Reduce 阶段）或数据量翻倍（用于 Broadcast/Allgather 阶段）。
-   **工作原理 (以 Allreduce 为例)**:
    1.  **阶段一：归约-散射 (Reduce-Scatter)**:
        -   在 $\log_2 N$ 步中，节点间的通信距离（步长）按 1, 2, 4, ..., N/2 的规律加倍。
        -   第 1 步 (距离=1): 节点 `i` 与节点 `i+1` 配对。它们交换自己数据数组的**一半**。一半用于累加、削弱，节点 `i` 发送前半部分给 `i+1`，接收 `i+1` 的前半部分并累加。同时节点 `i` 接收 `i-1` 的后半部分并累加，完成后，节点 `i` 保留累加的后半部分，节点 `i+1` 保留累加的后半部分。
        -   第 2 步 (距离=2): 节点 `i` 与节点 `i+2` 配对。它们交换的数据块是上一步归约后的结果，数据量仍然是数组的一半。
        -   依此类推。
        -   最终结果: 经过 $\log_2 N$ 步后，每个节点都只拥有整个数组的 `1/N`，但这 `1/N` 的部分是所有节点对应部分的全局归约结果。
    2.  **阶段二：全收集 (All-Gather)**:
        -   这个阶段是第一阶段的**逆过程**。
        -   第 1 步 (距离=N/2): 节点 `i` 与节点 `i+N/2` 配对。
        -   第 1 步 (距离=N/2): 节点 `i` 将前一步通信的节点对（例如 `i` 和 `i+N/2`）互相交换它们持有的 `1/N` 的最终结果。现在它们各自拥有了 `2/N` 的全局结果。
        -   依此类推。
        -   最终结果: 经过 $\log_2 N$ 步的相同操作，每个节点都逐步从邻居那里收集到了所有的归约数据块，最终恢复出完整的全局归约结果。
-   **示意图**:
    ![[图 10.10: HD 算法示意图]]

### 3. Ring 算法 (Ring-Allreduce)

-   **描述**: Ring-Allreduce 是一种高效的去中心化 Allreduce 算法，广泛应用于现代深度学习框架（如 Horovod、NCCL）。它将所有进程组织成一个逻辑环，数据在环中顺时针或逆时针传递。
-   **工作原理**: Ring-Allreduce 将数据分成 $N$ 个块 (chunk)，通过两个阶段，每个阶段 `N-1` 步完成归约和分发。
    1.  **阶段一：散射-归约 (Scatter-Reduce)**:
        -   分块: 每个节点都将自己的数据数组分成 $N$ 个小块。
        -   传递与累加: 在 $N-1$ 步中，进行循环传递。
        -   第 $k$ 步，每个节点 `i` 会将自己的块 `(i-k+N)%N` 发送给右邻居。
        -   同时，它会从左邻居接收块 `(i-k-1+N)%N`。
        -   最终结果: 经过 `N-1` 步后，每个数据块都完整地循环一周，并累加了所有节点对该块的贡献。此时，每个节点都拥有一个最终的、全局归约后的数据块 (具体来说是第 `(i-1+N)%N` 块)。
    2.  **阶段二：全收集 (All-Gather)**:
        -   用处: 现在每个节点都持有一个“最终版”的数据块，目标是让所有节点都拥有所有 $N$ 个“最终版”数据块。
        -   简单传递: 在接下来的 `N-1` 步中，节点们只是单纯地传递它们手中的“最终版”数据块，不再进行累加。
        -   最终结果: 经过 `N-1` 步后，所有最终块都在环上完整地跑了一圈，每个节点都收集到了所有 $N$ 个最终块，从而得到了完整的全局归约结果。
-   **性能特点**:
    -   **延迟**: 总共需要 `2 * (N-1)` 次通信步骤，延迟与节点数 `N` 成正比。

# 2.3 - LLM 并行策略

## 概述

大型语言模型（LLM）的训练和部署面临巨大的计算和内存挑战。为了克服这些瓶颈，需要采用各种并行策略。本笔记将深入探讨几种关键的并行策略，包括张量并行（TP）、序列并行（SP）和流水线并行（PP），以及它们如何协同工作以优化资源利用。

*   **相关概念**:
    *   Megatron-LM 中的 Ring-Allreduce (ringcp) 与 Ulysses 中的 Ring-Allreduce (ulysses cp) 的比较。
    *   MoE (Mixture of Experts) 系列模型。

## 一、张量并行 (Tensor Parallelism, TP)

张量并行旨在将单个 Transformer 层的计算和激活值分散到多个 GPU 上，以减少单个 GPU 的内存占用。

### 1.1 基本符号说明

在讨论并行策略时，我们使用以下符号：

-   $s$: 序列长度 (sequence length)
-   $b$: Batch size
-   $h$: Hidden size (隐藏维度)
-   $a$: 注意力头数 (attention heads)
-   $t$: 张量并行大小 (tensor parallel size)，表示将一层切分到 $t$ 个 GPU 上。
-   $p$: 流水线并行大小 (pipeline parallel size) - *注：在当前公式中未直接使用，但作为并行策略的一部分。*

### 1.2 激活内存公式：不并行 (单卡 / DDP)

在不进行张量并行的情况下（例如，单卡训练或使用数据并行 DDP），每层的激活内存占用公式为：

$Activations\ memory\ per\ layer = sbh(34 + 5\frac{as}{h})$

**公式拆解：**

-   $sbh$: 这是序列长度 $\times$ batch size $\times$ hidden dim，代表激活张量的**元素总数** (shape 为 $s \times b \times h$)。
-   $34$: 来自多个激活项的固定系数，例如 Q、K、V 投影、输出投影、MLP 中间状态、LayerNorm 输入输出等。
-   $5\frac{as}{h}$: 注意力机制的二次项。
    -   $a$ 个头，每个头有 $s \times s$ 的注意力分数矩阵。
    -   当转换为每个元素 ($sbh$) 的系数时，会得到 $5\frac{as}{h}$。

> **注意：** 当序列长度 $s$ 很大时，二次项 $5\frac{as}{h}$ 占主导地位，这是导致长序列激活内存爆炸的主要原因。

### 1.3 激活内存公式：张量并行 (TP)

当采用张量并行时，每个 Transformer 层的矩阵乘法被切分到 $t$ 个 GPU 上。因此，一些中间激活也会被切分，显存占用会分摊到 $t$ 张卡上。

$Activations\ memory\ per\ layer = sbh(10 + \frac{24}{t} + 5\frac{as}{ht})$

**各项含义：**

1.  **$10sbh$** (与 $t$ 无关的部分):
    -   LayerNorm (4 $sbh$)
    -   Dropout (2 $sbh$)
    -   输入到 Attention 和 MLP 的激活 (4 $sbh$)
    -   这些激活在张量并行中**依然在每个 GPU 完整保留**，因为 LayerNorm / Dropout 等操作通常需要全局激活信息。
2.  **$\frac{24}{t}sbh$**:
    -   来自 Attention 和 MLP 中的中间激活。这部分激活在张量并行后可以除以 $t$ 进行分摊。
3.  **$5\frac{as}{ht}sbh$**:
    -   注意力二次项的系数。由于每个 TP 组只负责部分注意力头，这部分内存也除以 $t$。

### 1.4 对比：张量并行效果分析

| 情况 | 激活内存公式 | 特点 |
|---|---|---|
| 无并行 | $sbh(34 + 5\frac{as}{h})$ | 二次项 $5\frac{as}{h}$ 影响大，长序列时内存占用巨大。 |
| 仅张量并行 | $sbh(10 + \frac{24}{t} + 5\frac{as}{ht})$ | 大幅降低二次项，但固定项 $10sbh$ 仍随 $s, b, h$ 线性增长，成为新的瓶颈。 |

**直观例子：**
如果 $t=8$，二次项几乎降低 8 倍。但固定项 $10sbh$ 依然随 $s, b, h$ 线性增长。
> 图中指出 “looking pretty good, but not quite there” —— 张量并行有帮助，但 LayerNorm / Dropout 这些未并行的激活仍会成为大模型瓶颈。

### 1.5 与 Flash Attention 的关系

第一张图提到：
> As with flash attention, we can drop this term via recomputation

-   公式中的 $5\frac{as}{h}$ 二次项主要来自于**存储注意力分数矩阵** ($a \times s \times s$)。
-   如果使用 **Flash Attention**，就不需要存储完整的 $s \times s$ 注意力矩阵，可以在反向传播时重新计算。
-   因此，这部分内存可以“去掉”。

**去掉二次项后：**

-   **无并行 (用 Flash Attention)** $\approx sbh \cdot 34$
-   **张量并行 (用 Flash Attention)** $\approx sbh(10 + \frac{24}{t})$

这更接近当前大模型训练的实际做法，Flash Attention 显著缓解了长序列的内存压力。

## 二、序列并行 (Sequence Parallelism, SP)

即使使用张量并行 (TP)，仍然存在一个与 $t$ 无关的 $10sbh$ 项，这部分内存无法通过 TP 降低。这 $10sbh$ 来自于 LayerNorm (4 $sbh$)、Dropout (2 $sbh$) 以及输入到 Attention 和 MLP 的激活 (4 $sbh$)。这些是**沿序列维度的逐点操作 (pointwise ops over the sequence)**，在原始 TP 中并没有被切分。

### 2.1 核心思路

序列并行的核心思想是：**把 LayerNorm / Dropout 这类沿序列维度的操作也切分到不同 GPU 上。**

图中 Transformer 层结构里标出的 **g** 操作：

-   **g (All-Gather)**: 前向时，把切分的序列拼回完整序列（用于 Attention / MLP 等需要全局信息的操作）。
-   **g (Reduce-Scatter)**: 前向时，把计算结果再切分回去。

反向传播时，这两个操作顺序相反。

**效果：**
原来每个 GPU 存储完整的 $s \times b \times h$ 的 LayerNorm 输入/输出，现在只存储 $\frac{s}{t} \times b \times h$（假设切分序列维度）。所以 $10sbh$ 项也除以 $t$。

### 2.2 激活内存公式对比表 (结合 TP, SP, 重计算)

| 配置 | 每层激活内存 |
|---|---|
| 无并行 | $sbh(34 + 5\frac{as}{h})$ |
| 仅张量并行 (TP) | $sbh(10 + \frac{24}{t} + 5\frac{as}{ht})$ |
| **张量 + 序列并行 (TP + SP)** | $sbh(\frac{34}{t} + 5\frac{as}{ht})$ |
| 张量并行 + 选择性重计算 (TP + Recompute) | $sbh(10 + \frac{24}{t})$ |
| **张量 + 序列 + 选择性重计算 (TP + SP + Recompute)** | $sbh(\frac{34}{t})$ |

**逐行解释：**

1.  **无并行**: 基准情况，二次项 $5\frac{as}{h}$ 很大。
2.  **仅 TP**: $10sbh$ 项不随 $t$ 变化，成为瓶颈。
3.  **TP + SP**: $34sbh$ (原来的 $10sbh + 24sbh$) 都除以 $t$ 了，二次项 $5\frac{as}{ht}$ 仍存在。
4.  **TP + 选择性重计算**: 丢掉二次项，但 $10sbh$ 项还在。
5.  **TP + SP + 选择性重计算**: **完美线性扩展**，只剩下 $sbh \cdot \frac{34}{t}$。

### 2.3 选择性重计算 (Selective Recomputation)

-   **描述**: 不存储所有中间激活值，而是在反向传播时重新计算某些层的前向结果。
-   **作用**: 能够去掉二次项 $5\frac{as}{h}$ (即注意力分数矩阵的存储)。
-   **代价**: 增加约 30–50% 的重计算时间。

### 2.4 结论：激活内存的线性扩展

通过结合**张量并行 (TP)**、**序列并行 (SP)** 和**选择性重计算 (Selective Recomputation)**，可以实现激活内存的完美线性扩展：

$Activations\ memory\ per\ layer = sbh \cdot \frac{34}{t}$

这意味着**每增加一倍 GPU ( $t$ 翻倍)，激活内存占用减半**。这是当前大模型训练（如 Megatron-LM）实现超长序列或超大模型的关键技术组合。

## 三、流水线并行 (Pipeline Parallelism, PP)

流水线并行是将模型的不同层分配到不同的 GPU 上，形成一个计算流水线。

### 3.1 优势

1.  **更节省内存，相比 FSDP (Fully Sharded Data Parallel)**: PP 只需要在 GPU 之间传递激活值，而不是完整的模型参数或梯度，因此内存开销相对较小。
2.  **通信效率更高**: 通信量主要取决于激活值的大小，并且通常是点对点 (point-to-point) 通信，而不是集合通信。这使得 PP 在通信带宽较低或延迟较高的环境中表现良好。

### 3.2 TP 在推理时的加速

*   **问题**: 为什么张量并行 (TP) 在推理时也能带来加速？
*   **简答**: 在推理时，TP 同样将模型的参数和计算分散到多个 GPU 上。虽然推理通常不需要存储梯度和中间激活，但对于非常大的模型，单个 GPU 可能无法容纳完整的模型参数。TP 允许模型参数跨 GPU 分片存储，并且每个 GPU 只计算模型的一部分，从而加速单个请求的处理时间，并允许部署更大的模型。
